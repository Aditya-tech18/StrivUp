# Publishing StrivUp to Google Play

StrivUp ships to Play as a **Trusted Web Activity** (TWA): an Android package
that opens the live site full-screen, with no browser chrome. There is no
second codebase. What is deployed to production is what the app shows, so a
Vercel deploy updates the app without a Play release.

This document is the runbook. Everything in the repo that the build depends on
is listed first, so you can tell what is already done from what is yours to do.

## What the repo already provides

| Piece | Where | Notes |
|---|---|---|
| Web app manifest | `src/app/manifest.ts` → `/manifest.webmanifest` | Bubblewrap reads this to seed the Android project |
| Icons | `public/icons/`, generated by `scripts/generate-icons.mjs` | 192/512 `any` + 192/512 `maskable`, plus a 1024 for the store listing |
| Service worker | `public/sw.js`, registered by `ServiceWorkerRegistrar` | Required for installability; network-first, see the file header |
| Offline screen | `src/app/offline/page.tsx` | What the worker serves when a navigation fails |
| Digital Asset Links | `src/app/.well-known/assetlinks.json/route.ts` | Reads two env vars, see below |
| Privacy policy (public) | `/privacy` | Play checks this URL loads signed out |
| Account deletion (public) | `/delete-account` | Required for any app with accounts |

To change the logo, replace `brand/strivup-logo.webp` and run
`node scripts/generate-icons.mjs`. Do not hand-edit anything in `public/icons`.

## 1. Pick a package name

Choose once and never change it: the package name is the app's identity on
Play, and a new one is a new listing with no reviews or installs.

```
app.strivup.twa
```

## 2. Generate the Android project

Needs Node 18+ and a JDK 17.

```bash
npm install -g @bubblewrap/cli
bubblewrap init --manifest https://<your-domain>/manifest.webmanifest
```

Answer the prompts with:

- **Package name** — `app.strivup.twa`
- **Application name** — `StrivUp`
- **Short name** — `StrivUp`
- **Display mode** — `standalone`
- **Status bar colour** — `#fbf9f9`, matching `themeColor` in `src/app/layout.tsx`
- **Splash colour** — `#ffffff`, matching `background_color` in the manifest
- **Signing key** — let Bubblewrap create one, then **back up the keystore and
  its passwords somewhere you will still have them in two years**. Losing it
  means you can never update the app under this package name again.

```bash
bubblewrap build
```

That produces `app-release-bundle.aab` for Play and `app-release-signed.apk`
for testing on a device.

## 3. Wire up Digital Asset Links

Without this the TWA runs with a URL bar pinned to the top of every screen.

1. Upload the bundle to Play Console once (an internal testing release is
   enough) so Play generates the app signing key.
2. Play Console → **Setup → App signing** → copy the **SHA-256 certificate
   fingerprint** under *App signing key certificate*.

   Take it from the **app signing key**, not the upload key. Play re-signs
   every bundle, so the upload key's fingerprint verifies on a sideloaded APK
   and then fails in production, which is a confusing afternoon.
3. Set both on the Vercel project (Production, and Preview if you test there):

   ```
   TWA_PACKAGE_NAME=app.strivup.twa
   TWA_SHA256_FINGERPRINT=AB:CD:...:EF
   ```

   Several fingerprints can be given comma-separated, which is how a key is
   rotated without downtime.
4. Redeploy, then check:

   ```bash
   curl https://<your-domain>/.well-known/assetlinks.json
   ```

   It must return your package and fingerprint. With the env vars unset it
   returns `[]`, which is a valid document that authorises nothing, so a
   preview deployment can never accidentally grant access.
5. Verify with Google's checker:
   `https://developers.google.com/digital-asset-links/tools/generator`

## 4. Play Console listing

Required before the app can be reviewed:

- **App icon** — `public/icons/icon-1024.png`, resized to 512x512 by the
  Console's uploader.
- **Feature graphic** — 1024x500. Not generated by this repo; it is a
  marketing image, not a derivative of the logo.
- **Phone screenshots** — at least two, 16:9 or 9:16, min 320px on the short
  edge. Capture from a device or from Chrome DevTools device mode at
  412x915 (Pixel 7). Worth capturing: Explore on the Quests tab, a quest
  detail page, the order verification sheet showing a code, and the feed.
- **Privacy policy URL** — `https://<your-domain>/privacy`
- **Data safety form** — answer it from what the app actually collects. The
  `/privacy` page lists it: account identity (name, email, phone, age,
  gender), photos the user uploads as proof, approximate location where a
  quest uses it, and app activity. It is not sold or shared with advertisers.
- **Account deletion URL** — `https://<your-domain>/delete-account`
- **Content rating** — complete the questionnaire. The app has user-generated
  content and social features, which affects the rating.
- **Target audience** — 13+. The privacy policy says the app is not for under
  13s, so do not tick a children's category; doing so pulls in Families policy
  requirements the app does not meet.

## 5. Before every release

```bash
npm run lint && npx tsc --noEmit && npm run build
```

The TWA points at production, so a bad deploy is a bad app for everyone
immediately, with no staged rollout to hide behind. Deploy, check the live
site on a phone, then ship the Play release.

## Things that will bite

- **Changing `start_url` or `id` in the manifest** after publishing makes
  Android treat it as a different app. Leave both alone.
- **The service worker caches build output.** A deploy changes the hashed
  filenames, so the new worker takes over on the next navigation. It does not
  cache pages or API responses, so no user-facing data can go stale.
- **Supabase auth redirects** must list the production origin. OAuth inside a
  TWA opens a Custom Tab and returns to the app via the same origin, so a
  missing redirect URL fails only on the installed app and not in a browser.
- **Play requires an account deletion path in-app**, not only on the web.
  Settings → Account → Delete Account covers it.
